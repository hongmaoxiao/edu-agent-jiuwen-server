# 01 信息架构：一条侧栏装下四种角色

## 1. 角色

智教云实际有四种角色，不是三种：

| 角色 | 范围 | 来源 |
|---|---|---|
| 运营 `operator` | 全平台 | 账号上的平台角色 |
| 学校管理员 `school_admin` | 一所学校 | 学校成员关系 |
| 教师 `teacher` | 自己任教的教学班；有建课权限的可以建源课程 | 学校成员关系、教学班角色 |
| 学生 `student` | 自己选的教学班 | 学校成员关系、教学班角色 |

一个账号可以同时有多个角色，比如某老师同时是本校管理员。普通账号有哪些角色，侧栏就同时出现对应的入口，不需要切换。只有演示账号能切换视角，见 §5。

保留学校管理员（11-03 已定）：多校运营时，开账号、排班、管预算不该都压在平台运营身上。

## 2. 侧栏方案

jiuwen 现在的图标侧栏是：任务、项目、专家、技能、扩展、实验，底部是设置、更新。新增入口后：

| 位置 | 入口 | 谁能看到 | 打开后 |
|---|---|---|---|
| 1 | 任务 | 所有人 | 原样不变：智能体对话、实训任务 |
| 2 | 项目 | 所有人 | 现有的品类 → 项目 → 实训。学生在这里学；教师、运营在这里预览学生看到的样子 |
| 3 | **成绩** | 学生 | 二级栏：我的作品、历史成绩、申诉、我的用量 |
| 4 | **教学** | 教师；有建课权限的人 | 二级栏：教学班、课程内容、评分规则、作品评阅、成绩册、申诉、用量 |
| 5 | **管理** | 学校管理员、运营 | 二级栏：运营看全平台，学校管理员只看本校。见下文 |
| 6–9 | 专家、技能、扩展、实验 | 所有人 | jiuwen 原有，不改 |
| 底部 | 设置、更新、**账号** | 所有人 | 账号：头像菜单，含个人信息与安全、当前学校、退出登录 |

几点理由：

- **「管理」合一个入口**：运营和学校管理员用的是同一批页面，区别只在数据范围。运营在二级栏顶部多一个「全平台 / 选择学校」的范围切换。这样运营不会看到一条十几个图标的侧栏。
- **二级栏沿用「任务」页的做法**：任务页在图标栏右边有一列会话列表。成绩、教学、管理三个入口都用同样的第二列放子页面，宽度、分组标题、选中态和任务页一致。jiuwen 只有一条侧栏，二级栏属于页面内容，不是第二条侧栏。
- **当前教学班、当前学校放在二级栏顶部**，取代智教云的 `X-Teaching-Space-ID`、`X-Organization-ID` 请求头和页头切换器。
- 智教云的「个人信息与安全」挪进账号菜单，不占侧栏位置。

学生看到的侧栏只多一个「成绩」，学习流程和现在一样从「项目」进入。

桌面版同样显示「管理」（11-03 用户确认），高风险操作要二次确认密码，见后端架构 §5。

### 不迁移

- 共享密码模式、免登录演示、请求头切换身份（`X-Demo-Role`）。演示改用 §5 的演示账号。
- 页头的四个「核对」面板（学习、申诉、管理、发布记录核对）。它们用来补救大 JSON 写入冲突；新库用事务和幂等键，失败就明确报错。
- Coze 自部署、代登录、凭据刷新。
- Cloudflare Worker 演示版（`db/schema.ts`、`drizzle/`）。

## 4. 学生端的数据从浏览器挪到服务端

现在线上是免登录演示：学习进度、指引勾选、提交材料和评测结果都存在浏览器 localStorage，平台不写库。登录上线以后（P2）：

- **提交材料、AI 初评、成绩**一律存服务端，教师才能评阅。
- **指引的面板状态**（展开、最小化、当前步）继续留在浏览器，属于界面偏好。
- **步骤完成情况和核查回答**随作品一起提交，是评分材料，存服务端。
- 已经存在浏览器里的演示记录不迁，演示站点保留到 P2 切换完成。

## 5. 演示账号与视角切换

11-03 用户要求保留演示能力：以后要用这个系统给客户演示，如果每换一个角色都要退出再登录，既麻烦，跳转也太突兀，客户看不懂。所以给**特殊的演示账号**一个视角切换器，在运营、教师、学生之间直接切换。

**怎么切**

- 演示账号登录后，账号菜单旁边常驻一个标签「演示 · 教师视角」，点开可以选运营、教师、学生。
- 切换后，侧栏入口立即按新视角变化，并停在新视角的默认页：运营到「管理 → 总览」，教师到「教学 → 作品评阅」，学生到「项目」。不刷新页面，不重新登录。
- 每个视角背后是演示学校里的一个固定演示身份：演示运营、演示教师、演示学生。学生视角提交的作品，切到教师视角就能评阅；切到运营视角就能看到这次用量。演示流程能连起来讲。

**边界**

- 只有标记为演示的账号能切换，普通账号没有这个入口，接口也会拒绝。
- 演示身份只属于演示学校。演示运营看到的「全平台」只包含演示学校，看不到任何真实学校、账号和用量。
- 全局设置在演示视角下只读，包括模型清单、单价、系统配置。
- 演示学校的数据可以一键重置回初始状态（`cmd/admin demo-reset`），重置不影响其他学校。
- 审计日志同时记演示账号和当时的视角。

**和智教云的区别**：智教云的视角切换靠请求头 `X-Demo-Role`，演示模式下所有人都能用，这一套不迁。新做法是服务端会话里记一个「当前演示身份」，只对演示账号开放。实现见 [后端架构](02-backend.md) §5。
